In this repository (the user's Licenciatura thesis project at ITeDA, on azimuthal asymmetries with the Pierre Auger UMD), the user has stated that all work must stay inside the repo folder — nothing should be written outside it, including scratch notes, review write-ups, or plan files. This overrides the general instinct to use a home-directory scratch location (like `~/.claude/plans/` or `/tmp`) for such artifacts; anything meant to persist (findings, review notes, analysis write-ups, scripts written to support a review) belongs inside the repository itself.

The user has since established a specific structure for this, which future sessions should follow directly rather than improvising:

- **`CLAUDE.md`** lives at the repo root (not buried in a worktree) — it's meant to be read by every session working in this repo, and should always be checked first before starting any work here, since it documents repo structure, known dead ends, and server-safety rules (including that git `add`/`commit`/`push` in this repo always requires the user's explicit permission first).
- **Finished work products** (review notes, analysis write-ups, verification scripts — anything Claude produces as a deliverable, as opposed to scratch/intermediate files) go under a top-level `claude_work/` folder, organized into topic-named subfolders (e.g. `claude_work/gap_notes_asimetrias_review/`) so it's clear what a given piece of work was about. Don't leave finished deliverables sitting loose at the repo root or stranded inside a worktree only — move them into `claude_work/<topic>/` once they're ready.
- The `.gitignore` excludes `.claude/` (Claude Code's own session/worktree/job state — not meant to be tracked or pushed) and `.ipynb_checkpoints/` (Jupyter's notebook save-state folders). Don't try to preserve or commit anything from inside `.claude/` itself — worktrees and job directories are disposable session mechanics, not deliverables; the actual deliverables should already have been copied out into `claude_work/` or the repo root (for `CLAUDE.md`) before a session ends.

When working in a worktree (as background sessions in this repo are expected to do), remember that files placed only inside `.claude/worktrees/<name>/` won't appear in the user's normal checkout or in tools like Jupyter Lab — the user works through JupyterLab, which only sees the main checkout and has no visibility into `.claude/` at all. Confirmed directly with the user: the fix is not to get the work onto a branch for them to check out — a plain file copy is enough and is what they actually want. Once a deliverable is ready, `cp` the finished files straight from the worktree into a new, clearly-named subfolder under `claude_work/` in the main checkout (e.g. `claude_work/<topic>_v2/`), without touching git at all. This works because the harness only blocks the Write/Edit tools from touching the shared checkout while a session is worktree-isolated — a `cp`/`Bash` copy to the main path is not blocked, and doesn't require exiting the worktree first. Making files show up this way is a separate concern from git entirely; committing/pushing still needs the user's explicit permission per the rule above, independent of whether the files are already visible in the checkout. Don't overwrite an existing deliverable folder in place — add a new versioned subfolder (e.g. `_v2`) alongside the original so both stay available for comparison.
